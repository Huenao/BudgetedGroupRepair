# Budgeted Group Repair（No-Baran Prompt）：实现与实验说明

## 1. 实现状态

当前工程同时保留冻结的 v1 初步实验和独立的 Router-v2 正式实验。代码包名为：

```text
budgeted_group_repair_no_baran
```

实现覆盖 Phase 0–3，包括：数据与 Baran reference 校验、安全抽样、四视角重叠候选组、No-Baran Prompt、DeepSeek 客户端、append-only checkpoint、实验一/二统计、uplift gate、次模 knapsack、外部 verifier、fallback、run validation 和报告生成。

冻结 v1 正式实证只执行了实验一和实验二；其 `C_not_supported` 判定和产物保持不变。Router-v2 使用新的 run ID、配置和 runner，将实验一、二视为诊断，完整执行 calibration、router、预算选择、selected-query union、verifier 和最终测试。

## 5. 数据

项目内保存完整的 14-dataset CARE 快照，manifest 冻结为：

```text
14 datasets
23,957 oracle error cells
```

正式前置实验选择 9 个数据集：

```text
source: hospital, flights, beers, rayyan, movies_1
tableeg: company, marketing, restaurant_20, soccer
```

这 9 个数据集共有 22,198 个 oracle error cells。按列使用 Hamilton 配额，以 seed 42 和 SHA-256 稳定排序，每个数据集抽样 300 个，共 2,700 个 cells。

## 6. 数据安全

`SafeCell` 的物理字段只有：

```text
suite, dataset, row, col, column, row_id, dirty_value
```

禁止加入 clean value、correctness、error type 和 TableEG annotation。`OracleCell` 只在响应文件写入完成后用于评价。

Prompt 构造器递归审计 system/user messages，禁止以下信息进入 provider request：

- Baran candidate、prediction、support、confidence、correctness；
- clean/right/correct repair；
- LLM correctness；
- error type、missing-value annotation、tuple pairs。

`information_policy` 进入 query ID、prompt hash、cache 和 run fingerprint，但不进入 messages。

## 7. 候选组实现

`group_generator.py` 生成：

```text
singleton / row / pattern / public_fd / semantic
```

对非 singleton 使用 `k ∈ {2,4,8}`。Pattern 和 semantic bucket 在同一 target column 内做 exact cosine average-linkage；小 bucket 使用 optimal leaf ordering，大 bucket关闭 optimal ordering但保持 exact sparse cosine distance。叶序上使用 half-stride exact windows，并补 tail window。

Baran 白名单字段只用于外部 `CellFeatures` 和 `group_features`，`GroupContextBuilder` 接收后立即丢弃，不会序列化到 Prompt。

每个候选 action 记录：

```text
group_view, group_size, bucket_id, cohesion,
same_row, same_column,
dirty_type_count, baran_type_count, baran_changed_share
```

## 8. Prompt 实现

System prompt 要求模型作为保守 candidate generator，为每个 target 独立返回：

```json
{
  "query_id": "...",
  "repairs": [
    {
      "cell_id": "...",
      "repair": "...",
      "confidence": 0.0,
      "decision": "propose | abstain",
      "evidence": "...",
      "affected_constraints": []
    }
  ]
}
```

User payload 由 dataset schema、group metadata、公开 FD components 和逐 target payload 组成。逐 target payload 包含 dirty value、masked row、column profile 和 5 个 similar dirty rows。

`query_id` 绑定 dataset、arm、view、有序 cell IDs、schema 和 information policy。`prompt_hash` 绑定完整 messages 与 completion ceiling，因此旧 schema 或任何消息变化都不能命中 cache。

## 10. Matched random partition

Random arm 在以下 strata 内稳定置换：

```text
(structured view, target column, singleton payload-length quartile)
```

置换后填回 structured group 槽位，保持：

- 完全相同的 2,280-cell population；
- 完全相同的 570 个 `k=4` group-size multiset；
- target column 与 payload length 分层；
- 相同 Prompt builder 和解析规则。

审计记录 fixed slots、exact group collisions、stratum count 和来源 structured query。

## 11. DeepSeek 客户端与 checkpoint

每个物理请求写入共享 append-only checkpoint。记录绑定：

```text
run binding fingerprint
query_id
prompt_hash
model and request fields
```

重试使用指数退避。Cache hit 和 checkpoint hit 不重复计入物理成本。Provider 返回的 model 必须精确等于 `deepseek-v4-flash`，否则立即失败。

Token cap 可以显式设定，也可用 `--no-token-cap` 授权不限 cap。存在 cap 时，调度器按已观测 token、unknown attempts 的保守估计和并发预留判断是否继续调度。

## 12. 解析规则

Parser 支持完整和 partial JSON response。对每个 action 中的 cell 必须物化一条结果：

- valid `propose`：使用返回 candidate；
- `abstain`：记为未修对；
- missing/invalid item：记为未修对；
- provider failure：组内所有目标记为未修对；
- unknown/duplicate cell ID：记录 parse issue，不扩张 action population。

所有失败保留在准确率完整分母中。

## 15. 实验一

### 15.1 目的

验证 Baran 与 No-Baran singleton LLM 是否存在可利用的 cell-level 互补性。

### 15.2 调用

生成 2,700 条 singleton responses。Model preflight 使用第一个 singleton action，因此正式 singleton batch 可以从共享 checkpoint 复用该物理响应。

### 15.3 指标

- 四格表 (n_{11},n_{10},n_{01},n_{00})；
- Baran/singleton accuracy；
- Oracle UB、UB−Baran、UB−Best；
- salvage/rescue；
- proposal precision、recall、F1；
- exact McNemar + Holm；
- row-cluster bootstrap，2,000 次，seed 45。

### 15.4 冻结结果

2,700-cell micro 结果：

```text
Baran accuracy       67.52%
Singleton accuracy   40.56%
Oracle UB            77.63%
UB − Baran           10.11 pp
UB − Best            10.11 pp
```

互补性门禁通过。

## 16. 实验二

### 16.1 目的

在相同 2,280-cell population 上回答：

1. structured group 是否优于或非劣于 singleton；
2. structured group 是否优于 matched random batching；
3. structured 是否节省 token/cell；
4. parse validity 和 missing rate 是否恶化。

### 16.2 调用复用

实验二直接引用实验一的 2,700 条 singleton ledger，只新调用：

```text
570 structured queries
570 random queries
```

### 16.3 统计

- structured−singleton：structured-query cluster bootstrap；
- random−singleton：random-query cluster bootstrap；
- structured−random：双向 query-cluster bootstrap；
- 2,000 次，seed 45，95% CI；
- per-dataset、macro、micro、worst dataset；
- actual provider usage 去重计费。

### 16.4 A/B/C 阈值

```text
noninferiority margin                 1 pp
minimum practical token saving       15%
maximum parse-validity drop           1 pp
maximum missing-item rate increase   1 pp
```

### 16.5 冻结结果

```text
Covered cells                         2,280
Structured groups                     570
Structured micro accuracy             39.30%
Matched singleton micro accuracy      39.69%
Structured − singleton micro          −0.39 pp
Structured − singleton macro          −0.39 pp
95% CI                                [−1.47, +0.63] pp
Structured − random macro             +1.64 pp
Macro token/cell saving               27.46%
Worst dataset                         movies_1, −3.125 pp
Decision                              C_not_supported
```

CI 下界低于冻结的 −1 pp 非劣界，因此成本节省不能使总体判定升级为 B。`grouping_supported=false`。

## 18. Phase 2.5 与 Phase 3

`run-routeability` 使用 family holdout/cross-fitting 训练 helpful/harmful gate，并检查 AUC、calibration、uplift ranking 和 harm control。`run-bgr` 使用保守收益、实际 query cost 和预算份额运行 lazy gain/cost optimizer，再通过 verifier 决定 `accept_llm | keep_baran | reject`。

以下门禁必须全部为真：

```json
{
  "complementarity_supported": true,
  "grouping_supported": true,
  "routeability_supported": true
}
```

当前正式 v1 run 为：

```json
{
  "complementarity_supported": true,
  "grouping_supported": false,
  "routeability_supported": null,
  "phase3_allowed": false
}
```

因此当前不得宣称完整 BGR 已被实证支持。

### 18.1 Router-v2 正式协议

Router-v2 与上述 v1 hard-gate 流程物理隔离：

- calibration 使用全部 9 个 TableEG 数据集的 5,543 个 singleton queries，并为每个数据集按 `view × size × cohesion quartile` 最多抽样 300 个 non-singleton queries；
- 正式测试只覆盖指定 9 个目标数据集的 22,198 cells；
- 候选组大小为 `1/2/4/8`，预算为全量 singleton estimated tokens 的 `1/5/10/20/50%`；
- 20% 预算另报告 singleton-only 和 singleton + exact-4；
- LightGBM 和 XGBoost 分别进行 family-holdout 训练和独立选择；
- Baran type、format、support、changed 等字段可以进入 router 特征，但 No-Baran LLM messages 通过递归审计禁止任何 Baran candidate/diagnostics；
- routeability 指标只诊断，不阻断；数据泄漏、预算、模型、Prompt、request identity、run fingerprint 与最终覆盖仍是 hard gates。

对应分阶段命令为：

```text
plan-router-run
run-router-calibration
train-router
run-bgr --router-v2
validate-run --require-router
finalize-run --require-router
report --require-router
```

## 22. 复现实验注意事项

- 新实验必须使用新的 run ID；
- 不得把旧 response 复制到不同 query ID、schema 或 prompt hash；
- 不得在 action 冻结后调整分组、阈值或 cell population；
- 不得用 clean labels 选择 group 或调参；
- 不得因 provider failure、missing 或 abstain 缩小分母；
- 不得回改或绕过冻结 v1 的 historical hard gate；Router-v2 必须使用独立 run ID 与独立配置；
- 报告结论必须与 `decision_gates.json` 和可独立重算指标一致。
